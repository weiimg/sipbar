# Sipbar 設計與決策

[← 回 README](../README.md)

這份記錄每一個決定的理由，以及過程中判斷錯的地方。**不是使用說明**——
怎麼裝、怎麼用在 README。

## 檔案

版面只有一條規則：**產生器在 `tools/`，它們的產物在 `assets/`，程式在 `src/`。**
字體與圖示都是產物，兩個都不該手改。

| 檔案 | 說明 |
|---|---|
| `run.bat` | 啟動正式版（無 console） |
| `src/island.py` | **正式版**，動態島。唯一的入口 |
| `src/settings.py` | 設定的讀寫、體重與作息推導、開機自啟、資料清除 |
| `src/onboard.py` | 首次啟動的引導（三頁，含動態島的動畫預覽） |
| `src/theme.py` | 深色／淺色調色盤 |
| `src/menu.py` | 系統匣與右鍵選單（自繪，不用 QMenu） |
| `src/typeface.py` | 隨程式散布的字體：載入、驗證、產生 QFont |
| `src/dashboard.py` | 紀錄的統計計算（只算數字，不畫） |
| `src/stats_window.py` | 紀錄視窗與設定頁（只畫，不算） |
| `assets/fonts/` | `WaterPet Sans TC` Bold + Medium（建置產物）＋ 兩份 OFL |
| `assets/icon.ico` | 應用程式圖示（建置產物） |
| `tools/build_font.py` | 產生上面那兩個字體：Inter 的拉丁 + Noto Sans TC 的中文 |
| `tools/make_icon.py` | 產生 `assets/icon.ico`（二進位，沒有產生器就改不動） |
| `tools/fontsrc/` | 建置字體用的來源，不隨程式散布 |

`pet.py`、`run_pet.bat`、`island_prototype.py` 已於 2026-08-15 移出專案，
放在 `..\archive\喝水提醒桌寵-legacy_2026-08-15\`。它們各自有一套設定讀寫、
早已跟正式版不同步，留在專案裡只會讓發布出去的程式碼多兩個沒人維護的入口。
**唯一的入口是 `src/island.py`。**

**程式旁邊不放 `config.json`。** 那個位置是 `settings.py` 認定的「舊版設定」，
會被搬進使用者的 `%LOCALAPPDATA%\Sipbar\`——只要它跟著發布出去，
每個新使用者一裝就繼承開發者的個人設定，而且完全沒有提示。`.gitignore` 擋著它。

## 開機自啟

在設定頁用「開機時啟動」開關控制。它寫的是登錄檔：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Sipbar
```

**用登錄檔而不是 Startup 資料夾的捷徑**，因為工作管理員的「啟動應用程式」分頁
看得到也關得掉——Startup 資料夾裡的捷徑反而是使用者找不到的那一種。
舊版那個 `Startup\喝水動態島.lnk` 已於 2026-08-15 移除（封存在 `..\archive\` 裡）。

開始選單的 `喝水動態島.lnk` 保留著，那是給「Win 鍵打『喝水』」用的，跟自啟無關。
**一個平常隱藏的常駐工具，必須有一個「程式沒在跑也找得到」的入口。**

## 第一次啟動：引導

`onboard.py`，三頁，全部加起來只問**一個**問題。

規劃階段列了四題（水壺、體重、幾點睡、螢幕），但那是程式還不會自己推導時寫的。
現在目標由體重推、體重可留空、起床時間從活動紀錄推、單螢幕根本不顯示螢幕選項——
**第一天問得到、而且問了會改變成敗的，只剩「桌上有沒有水」。**

而那根本不是設定，是一個行為介入。規劃文件裡最重的一句：

> 先在桌上放一個大水壺，這個工具才有意義。工具解決不了物流問題。
> 這是整個計畫成敗最大的單一因素，而它跟寫程式無關。

所以那一題單獨占一頁。跟體重並排會讓它讀起來像同一類東西，它不是——
它是唯一一個答錯會讓整個工具失效的問題。

| 頁 | 內容 |
|---|---|
| 開始之前 | 「桌上現在有水嗎？」→ 有／還沒有 |
| 先去裝一壺 | 只在答「還沒有」時出現。**不擋**，按鈕隨時可以按 |
| 這樣用 | 動態島的動畫預覽、三條操作、設定入口、開機時啟動 |

不擋是刻意的：文案已經把話說清楚，第一次用就被鎖住只會讓人直接關掉程式。

### 為什麼要演一次動畫

這個工具最大的可發現性問題是它平常完全隱藏。文字寫「時間到才從螢幕頂端滑下來」，
讀的人得自己想像那是什麼樣子；**演一次就不用想像。**

預覽用的是跟本體同一套彈簧物理（`motion.py`），所以引導裡的手感跟實際看到的一致。
循環是 3.4 秒：藏在螢幕上緣後面 → 滑下來展開 → 游標點一下 → 變成已記錄 → 滑回去。
（初版 4.2 秒的循環有 1.7 秒是空的，看起來像壞掉。**死時間要少。**）

按下「開始」之後不是直接進背景，而是讓**真的**動態島滑下來打一次招呼。
引導裡演的動畫是在視窗裡，跟它實際會出現在螢幕哪個位置是兩回事，
演完再讓本尊出來一次，才補得上那個落差。

### 三頁高度不同，視窗用彈簧補間

三頁的自然高度是 239 / 197 / 565。硬拉成同高（`QStackedWidget` 的預設行為）
會讓第二頁有七成是空的，讀起來像沒做完。

所以頁面維持自然高度，視窗高度走彈簧補間，**中心線鎖在切換的那一刻**、往兩邊長。
不鎖的話高度只往下長，走到第三頁會掉出螢幕。

補間中途不能把內容壓扁——`IslandPreview` 是固定尺寸，壓下去就是切掉。
做法是讓頁面保持自然高度、由容器裁切：長高變成「內容從上往下露出來」，
正好是引導往前走的方向。`tests/render_onboard.py` 逐格檢查高度不倒退、
不掉出螢幕、中心不偏移，並確認每一頁停下來時剛好包住自己的內容。

### 已經在用的人不會再看到它

`onboarded` 這個鍵是後來加的。舊版寫的設定檔沒有它，如果直接用預設值 `False`，
**已經用了兩週的人升級之後會被問「桌上現在有水嗎」**——搞錯對象。

所以 `_upgrade_keys()` 對「檔案已存在但沒有這個鍵」的情況補成 `True`。
全新安裝寫進檔案的是明確的 `False`，`setdefault` 不會去動已經存在的鍵，
所以中途關掉引導的新使用者下次還是看得到。`test_settings.py` 第 7b 節釘住兩邊。

要重看走設定 →「關於」→「使用說明 / 重看」。

### 彩蛋

「桌上現在有水嗎？」按「還沒有」，會用預設瀏覽器開巧虎的喝水歌，邊裝邊聽。

這是整個程式唯一一個會離開自己、也是唯一會用到網路的動作。所以「關於」那頁的
隱私聲明**不能**寫「本程式無網路連線」，寫的是「不蒐集也不傳送任何資料，
全部僅儲存於本機」——那句才是真的。**寫得出來的保證才寫。**

開不起來也不影響流程，`QDesktopServices.openUrl()` 包在 try 裡。
（這個專案有過一次教訓：把成敗押在作業系統的檔案關聯上，`webbrowser.open()`
靜默失敗、什麼都沒發生也查不出來。）

## 節奏（依你的實際狀況設的）

- **計時基準是「在電腦前的連續時間」**，不是牆上時鐘。鍵鼠閒置 15 分鐘就暫停計時，回來續計。
  提醒發在你不能行動的時候，只會訓練出無視的反射——那個反射會連 Discord 提醒頻道的工作提醒一起污染。
- **多久跳一次：白天約 64–86 分鐘一次**（預設 75 分鐘 ±15% 隨機抖動，抖動是為了對抗「整點提醒」的可預測性）。深夜起拉長成 1.45 倍，也就是約 109 分鐘。
  但那是「在電腦前的時間」，不是牆上時間——離開電腦超過 15 分鐘就暫停計時，所以實際可能兩小時才跳一次。
  **不用記這個數字**：把滑鼠移到螢幕上緣中間，它會直接告訴你「下次約 25 分後」。
- 每日目標 7 次（估算約 1400cc，只算來自提醒的部分）。達標後當天不再出現。
  間隔在設定裡可選 30 / 45 / 60 / 75 / 90 分。

### 這些數字怎麼來的（依國健署資料推算，以下用 65kg 舉例）

- **每日白開水目標 = `體重 × 30cc`**，65kg 就是約 1950cc，與國健署「成人每日 6–8 杯（240ml/杯）＝ 1440–1920cc」相符。程式用的是你自己填的體重，留空則用預設值。
- **每次約 200cc、小口慢喝**：國健署明講 1 小時內不喝超過 1000cc，一次灌下去身體來不及吸收。
- **1950 ÷ 200 ≈ 一天 10 次**，但工具只在你坐電腦前時計時。起床那杯（國健署建議 300–500cc）與三餐湯水在它管不到的地方，所以工具承擔 **7 次**。
- **7 次 × 75 分鐘 = 525 分鐘 ≈ 8.75 小時**，剛好鋪滿一個工作日的電腦時間。原本的 6 次 × 60 分鐘只有 6 小時，會在下午就達標、然後整晚安靜。
  （70 是手算的結果，但面板上的選項是 30/45/60/75/90，**預設值必須是其中之一**——
  否則分段控制項一打開就顯示「最接近的那個」，使用者什麼都沒改，設定卻已經跟實際值不一樣。）

夏天在外拍攝、流汗多的日子要另外補，工具管不到那段。這是一般性的公共衛生資訊，不是針對個人健康狀況的醫療建議。
- **深夜起間隔拉長成 1.45 倍**（75 分 → 109 分），文案有一半機率換成「小口就好」。晚睡的人一樣需要提醒，但半夜灌水會壞掉睡眠。
- **一天的分界在「習慣起床時間」，不是午夜。** 不然你凌晨兩三點的工作會被切成兩天，次數莫名歸零。
  這個值程式會推、使用者可以改，見下面「為什麼問『起床時間』而不是『換日時間』」。
- 拍攝日電腦沒開就完全不計時，不累積罪惡感。
- **計時與狀態都會跨重啟保存。** 開機自啟、程式當掉、手動重開都不會把累積的時間丟掉，間隔也不會重擲。
  狀態一併存著：不存的話重開一律從「正常」起算，而累積時間已經超過間隔，
  下一個 tick 就會再發一次提醒。**那不只是煩**，多出來的 remind 事件會混進活動紀錄，
  把作息推導用的安靜段填掉（實測三筆就讓推導直接回 None）。
  每分鐘落檔一次，加上啟動時與每次補水／暫停都會存，所以最多只會丟一分鐘。
  距上次存檔超過 12 小時（睡了一覺、電腦關一整天）才會重新開始一段。

## 動畫

用彈簧物理，不是 easing curve——這是蘋果 UI 動畫跟一般網頁動畫最根本的差別。easing 是預先畫好的曲線，被打斷只能從頭再走；彈簧有速度與慣性，被打斷時帶著當下的速度轉向新目標。

| 用途 | response | damping | 過衝 | 收斂 |
|---|---|---|---|---|
| 展開 | 0.40 | 0.70 | +2.0% | 567ms |
| 收合 | 0.52 | 1.00 | 0% | 1100ms |
| 現身 | 0.46 | 0.72 | +1.7% | 667ms |
| 隱藏 | 0.36 | 1.00 | 0% | 833ms |
| 內容 | 0.34 | 1.00 | 0% | 800ms |

覺得手感不對就調這幾個數字（在 `island.py` 的 `_target_expand` / `_target_reveal` / `_target_content`）。**response 是週期，越小越快；damping 越小彈越多，1.0 完全不過衝。**

## 字體

`FONT_FAMILY` / `FONT_TITLE_PX`（20）/ `FONT_SUB_PX`（15）在 `island.py` 開頭。

字級調大之後藥丸也要跟著加寬（展開尺寸 384→430），否則小標會被省略號截掉。
測試 17b 會用字體度量檢查最長的三段文字放不放得下——**改字級或改目標次數時，先跑它**。

> **一個被推翻兩次的說法**：先前這裡寫著「半透明視窗用不了 ClearType，只能灰階抗鋸齒」。
> 那是錯的，而且後來又被錯誤地「復活」過一次——用 `widget.grab()` 量，
> 半透明視窗的彩色像素是 0.0%、不透明是 80.1%，看起來鐵證如山。
>
> **但 `grab()` 是把 widget 重畫進一張離屏 pixmap，那條路才是灰階抗鋸齒。**
> 改成抓桌面（DWM 真正合成出來的像素）之後：同一段字、同一個純灰階筆色，
> 半透明與不透明兩張截圖 **MD5 相同、0 個像素不同**，都有 70% 以上的次像素著色。
>
> **要量渲染，就得量螢幕。** 離屏渲染跟螢幕是兩條路，拿前者當後者的證據，
> 會得到一個很有說服力的錯誤結論——這個錯誤差點讓整組視窗改成不透明去換一個
> 本來就已經有的東西。

**字體現在隨程式散布**（`assets/fonts/`，見 `typeface.py`）。以前是假設機器上裝了
Noto Sans TC——那對自用成立，發布出去就不成立，而且要不到時 Qt 是**靜默替換**的。

> **字體序列裡每多一個字體，就多幾百 MB。** 一度把 fallback chain
> 掛在 QFont 上當保險，結果島畫出文字後記憶體從 89MB 漲到 612MB、handle 從 342 到 1153。
> `tests/test_font_memory.py` 把這條線釘住了。

### 英數字用 Inter，而且是合成進同一個檔

隨附的 `WaterPet Sans TC` 是**建置產物**：Inter 的拉丁字形（101 個碼位）寫進
Noto Sans TC 的 CFF，其餘兩萬多個字形原封不動。產生器是 `tools/build_font.py`。

換 Inter 的理由是數字：Noto Sans TC 的數字在介面上偏窄、字腔小，而這個工具的
畫面幾乎全是數字（連續天數、今天 3/7 次、08:00、還剩 109 分）。

**為什麼不能像 CSS 那樣寫 `font-family: Inter, "Noto Sans TC"`：**

| 做法 | 島畫出文字之後的記憶體 |
|---|---|
| 單一家族，自己蓋得住全部的字 | 56 MB |
| `setFamilies(["Inter", "Noto Sans TC"])` | 396 MB |
| 只掛 Inter，中文交給系統回退 | 394 MB |
| 兩個獨立字體，各自只畫自己蓋得到的字 | 56 MB |

規則不是「中文字體很貴」，是**只要 Qt 需要為任何一個字做回退，
它就把一整份中文字符表載進來**。貴的不是 Inter（2,849 個字符），
是被迫整份載入的 Noto（20,745 個）。

「兩個獨立字體」成本是零，但會讓同一張卡出現兩種數字設計（「08:00」是 Inter、
正上方的「23:00 起改為每 109 分」是 Noto），那看起來像 bug 不像設計。
所以離線合成，出貨單一家族。

**數字取的是 Inter 的等寬那一組**（`tnum` 底下的 `.tf` 字形，全部同寬）。
Inter 預設的數字是比例寬（`1` 是 415、`0` 是 646），那對內文是對的、對介面是錯的：
這個介面的數字全都會變，比例寬會讓數字一變、旁邊的東西就跟著左右跳。

**空白、間隔號、中文刻意不換。** 原則是「出現在拉丁字串裡的才換，
出現在中文行裡的維持 Noto」——`·` 兩邊都是中文，那個位置該用中文字體的版本。

**轉檔前一定要合併重疊輪廓。** Inter 的 `#` 是四條同方向的橫豎條疊在一起
（`+` 兩條、`×` 兩條、`4` 兩條），靠非零環繞填成實心。TrueType 這樣畫沒問題，
**但 CFF 的柵格化假設輪廓不重疊**——直接搬過去，筆畫交叉的地方在小字級會變成白的。

> 這個症狀騙過了兩道檢查：256px 的逐像素比對是乾淨的（0.57%），字樣圖上看得到
> 卻被當成點陣放大的假象。**它只在介面真正用的 15px 出現**，最後是使用者回報
> 「筆畫交叉的地方會變白色」才抓到。教訓是：**症狀有尺寸依賴時，
> 就得在真正會用到的尺寸上驗。**

`tests/test_font_build.py` 守八件事：Qt 真的解析到這個家族與字重、中文一個都沒少、
直排度量一格都沒變（變了整個介面的行高就要重排）、換過的字寬度等於 Inter、
沒換的等於 Noto、數字等寬、每個字形逐像素比對 Inter 本尊、介面用到的每個非中文
字元都判斷過要不要換、以及**沒有重疊輪廓**。

最後那條用有號面積判斷：各輪廓的有號面積相加，沒有重疊時剛好等於實際填色的面積；
同方向的輪廓一重疊，重疊處就被算兩次。實測在修之前會抓到 6 個字形（面積多算 4–13%）。

> **這條路上的失敗全是靜默的。** T2 charstring 的寬度是相對 `nominalWidthX` 編碼的，
> 傳實際寬度進去的話 hmtx 仍然正確、fontTools 讀得出來、檔案也開得起來，
> 只有真的畫出來才會發現每個數字都寬了一倍。那一版通過了所有結構檢查，
> 是 `test_island` 第 17b 節用字體度量量出「連續 128 天…」多了 72px 才擋下來。

真正有效的三件事：

1. **字型用 Noto Sans TC，內文用 Medium 500。**
   實測比較過 default / freetype / gdi 三種引擎與三種字型：引擎差異不大，
   但 Microsoft JhengHei UI 的 Regular 筆畫太細，淺色字在深色底上因 gamma 更顯薄。
   關鍵是 **Noto Sans TC 有真正的 Medium 500（精確匹配），JhengHei UI 只有
   Regular / Light / Bold**——沒有中間字重可以補償。
2. **靜止時不套任何變形。** 非整數的位移或縮放會讓 Qt 關掉 hinting，字就糊。
   動畫進行中才套，一停下來就歸零。
3. **尺寸用像素不用點數**（點數會經 DPI 換算成小數），需要精確對齊時用字體度量算整數基線。

60fps 迴圈只在彈簧還在動的時候跑，靜止就停——常駐工具不能無條件重繪。
實測 CPU 0.4%、RAM 約 84MB（比先前的 59MB 多的部分是隨程式散布的字體）。

## 設定

右鍵島或系統匣 →「設定」，或在紀錄視窗右上角點齒輪。改完即時生效，不用重開。
（節奏類的變更等下一輪才套用——見下方「改設定不能重置倒數」。）

### 設定的擁有權

**島擁有它的 `cfg`，紀錄視窗拿一份副本編輯，改完往上回報。**

視窗一度直接持有島傳來的那個字典。設定頁改完後 `self.cfg.update(...)` 就地改掉了
島的狀態，於是島的 `apply_config()` 在算「哪些鍵變了」時，舊值早就是新值——
`changed` 永遠是空的、直接 return。結果是換螢幕、改目標這些**需要副作用**的設定
完全沒有作用，而且連一行事件紀錄都不會留下，沒有任何錯誤訊息。

（提醒間隔看起來還會生效，是因為兩邊共用同一個字典的意外副作用，
不是因為那條設計好的路真的走通了。）

`apply_config()` 現在也自己複製一份舊值，不依賴呼叫端記得不要共用。
`test_settings.py` 第 11b 節用**共用同一份 cfg** 的真實條件測——
先前的測試傳的是獨立字典，剛好繞過整個問題。

分成三張卡：**提醒 / 顯示 / 關於**，加上跟卡片隔開的「清除紀錄」。
由上而下就是動線：喝多少 → 它長什麼樣 → 這程式是什麼 → 重來。

「關於」裡有「使用說明 / 重看」，會重開首次啟動的那三頁引導。
**一次性的教學一定要留一條回去的路**，否則使用者只有一次機會看懂它怎麼用。

可調的只有六項，篩選標準一條：不改就會讓工具對這個人失效。

| 設定 | 為什麼它活下來 |
|---|---|
| 體重（可留空） | 50kg 和 90kg 的目標差一倍，這是唯一擋不掉的個體差異 |
| 提醒間隔 | 每個人在電腦前的時間結構不同 |
| 習慣起床時間 | 一天從幾點開始算。程式會給初始建議，但推導對雜訊敏感，必須能改 |
| 外觀 | 跟隨系統／淺色／深色 |
| 島顯示在哪個螢幕 | 多螢幕猜不到（只有一個螢幕時不顯示這一項） |
| 開機時自動啟動 | 沒人會自己去 Startup 資料夾 |

### 一個區塊必須自己說得出它是幹嘛的

「夜間自動放慢」一度自成一張叫「排程」的卡：一整張只為了顯示一個不能改的值，
底下還附一段解釋睡前為什麼不該喝水。使用者看到的是一個讀不出用途的區塊——
**「排程」是系統術語，而那個值離開了它的脈絡就沒有意義。**

現在它緊接在「提醒間隔」後面，讀起來是一句話：平常 75 分，晚上 23:00 起改成 109 分。
說明只寫這個數字**從哪來**（依活動紀錄推算），不寫**為什麼要有這個機制**。

> **一個區塊如果需要一段文字才說得清它為什麼存在，多半是它放錯地方了，
> 不是說明寫得不夠好。**

### 為什麼問「起床時間」而不是「換日時間」

「換日」是系統概念，使用者得反推該填什麼；起床時間是他本來就知道的事實。

而且**語意上更對**。程式推導出來的安靜段起點其實是「你停止用電腦的時間」，
拿它當換日有個破口：哪天你做過頭做到那個時刻之後，換日會在你還在工作時
把當天次數歸零、前一天的紀錄當場被切斷。起床時間沒有這個問題——
你還在電腦前就代表還沒睡，那就還是同一天。

### 排程為什麼分成兩條各自推導

深夜模式原本是「換日 − 6 小時」。換日改成起床時間之後那條公式就沒依據了
（起床 11:00 會推出深夜模式 05:00，完全反了），所以拆開：

- **起床時間** = 最長安靜段的**結束**（你回到電腦前的時刻）
- **深夜模式起點** = 每天最後一次活動的**中位數** − 3 小時

「每天」由起床時間定義，所以第二條建立在使用者已經給定的值上。
往前 3 小時是有依據的：睡前 2–3 小時的攝取才是造成夜間起身的區間。

取中位數不取平均：一次特例（熬夜、或程式重啟造成的雜訊事件）會把平均拉走，
卻撼動不了中位數。**連續段偵測則相反——實測三筆多餘的事件就讓它從 6 小時
縮到 3 小時、直接回 None。** 這正是起床時間必須可手動調整的理由。

還有一道防線：使用者可以把起床時間設在自己實際還在活動的時段裡，
那時「一天」的邊界會切在活動中間，中位數變成 23 小時、推出 07:00 這種垃圾。
清醒時段落在 8–20 小時之外就代表前提不成立，退回「起床 − 11 小時」。

### 捲動：設定可以，紀錄不行

紀錄那三頁不捲動，理由在下面「刻意拿掉的東西」那節：成就與軌跡是要讓人逛的，
藏在捲軸下面等於不存在。

**但設定不是拿來逛的，是拿來查的**——帶著「我要改間隔」的目的進來，找到、改完、離開。
這種頁面捲動是標準做法。所以規則從「一律不捲」改成依頁面性質決定。

視窗高度不變（跟紀錄頁一致，含陰影 756），捲的是內容區——換頁時視窗不會跳動。
捲軸自繪：細、圓角、軌道全透明；內容區上下緣各一道 18px 的漸層，暗示「還有」。
那道漸層是還債：不捲動的面板一眼就知道有多少東西，捲動的沒有。

（第一版把漸層做成 28px，結果它蓋到完整顯示、讀得到的那幾行，
把說明段落洗成半透明。遮罩的作用是暗示還有，不是把內容變淡。）

### 版面用網格，不是逐項微調

設定列看起來「沒排好」，多半不是對齊錯了，是**每一列高度都不一樣**——有說明的列
自己長高、沒說明的列自己縮短，右側控制項的中心線每列落在不同地方，眼睛掃下來就是歪的。

所以列高釘死成四種，全部是 8 的倍數（`stats_window.py` 開頭的網格常數）：

| 常數 | 值 | 用在哪 |
|---|---|---|
| `ROW_TALL` | 64 | 有說明的設定列（標題 + 說明兩行） |
| `ROW_FLAT` | 48 | 單行的設定列。裡面有控制項，要留得下點擊區 |
| `ROW_INFO` | 40 | 唯讀資訊列。沒有東西要點就不需要那個餘裕 |
| `ROW_SECTION` | 32 | 區塊標題 |
| `LABEL_GAP` | 2 | 標題 ↔ 它自己的說明（同一組，貼緊） |
| `ROW_GAP` | 8 | 列 ↔ 列（不同項目，拉開；分隔線落在中間） |
| `CTRL_H` / `CTRL_W` / `CTRL_TYPE` | 34 / 240 / caption | 設定裡控制項的高、寬、字級 |

兩件跟比例有關的事：

- **接近性原則：標題與說明貼緊，列與列拉開。** 兩者是同一組資訊，靠得近才讀成一組；
  真正需要距離的是「這一項」與「下一項」之間。`LABEL_GAP` 與 `ROW_GAP` 要一起看，
  單看一個數字判斷不了夠不夠。
  （做反過一次：把 `LABEL_GAP` 加大到 6，結果標題與說明散開、列與列反而還是黏著。）
- **控制項比它標示的內容矮一級，而且字級要跟著縮。** 設定裡的分段控制項是
  34 高、240 寬、15px 字；導覽用的那條（今天／紀錄／成就）維持 40 與 18px，
  因為那是這個視窗的主要動作。控制項一度是 40 高、280 寬，在 706px 的內容區裡
  佔掉 40%，比標籤還搶眼。**只縮外框不縮字，字會把框撐滿，看起來仍然很重。**

> 這四個值一度是 48/40/32/24——那是為了把設定頁擠進 558px 壓出來的，不是設計判斷。
> 改成可捲動之後就沒有理由再擠，各放寬一級。**版面被空間逼出來的妥協，
> 要在空間解禁時退回去**，不然那些妥協會被後人當成刻意的設計而繼續沿用。

**互動列比資訊列高，是因為滑鼠需要空間，不是為了好看。** `test_settings.py` 第 12d 節
會擋下任何不在這四種之列的列高。

### 幾條寫死的規矩

- **單位貼在控制項旁邊**（`65` **公斤**、`75` **分鐘**），不寫進說明裡。單位是那個值的
  一部分，塞進說明就變成要讀完一句話才知道自己在設什麼。
- **不用內部術語。** 「換日」「深夜模式」使用者讀不出是什麼，還會誤解成「幾點睡」。
  改成講他本來就知道的事實、並把結果的數字寫出來：「習慣起床時間 ／ 次數將於每日重置」、
  「夜間自動放慢 ／ 23:00 起改為每 109 分」。

### 介面文案有兩套標準，而且用機器守

**島的訊息**（「口渴了」「水呢」「你贏了」）是角色的聲音，口語是刻意的——
那是這個工具的設計核心之一。程式碼裡用 `# copy-style: off` / `on` 標出來。

**介面本身的文案**（設定項、選單、按鈕）是標籤不是對話：名詞或動詞片語、
不用第二人稱、不解釋機制或後果、不用語助詞。

`tests/test_copy_style.py` 擋四類東西（`island.py`、`stats_window.py`、`menu.py`、
`onboard.py` 全在檢查範圍內，角色台詞用 `# copy-style: off` 標出來例外）：

1. **語域**，「你／自己／就會／才會／不然／之後要／喔／吧」這類徵狀
2. **冗贅**，逗號兩邊出現同一個雙字詞，後半句多半是把前半句再講一次
3. **破折號**，介面用標點分隔就好
4. **用單字代替詞**，例如「島顯示在」的「島」。單字看起來省，
   但它把「這是什麼」的判斷丟給讀者：讀過整份文件的人知道那是動態島，
   第一次打開設定的人不知道

第二條是為了 `以在電腦前的時間計算，離開電腦不算` 這種句子加的：第一句已經把話
說完，第二句只是換個說法重複，讀的人得讀兩遍才確定沒有新資訊。**那是冗贅不是
用詞不當，所以違禁詞清單抓不到。** 用「共用雙字詞」當訊號，對現有文案零誤報，
而且順帶抓出一句沒人注意到的：`一般性建議…非醫療建議`，「建議」重複兩次。

它仍然抓不到全部——沒有正規表達式判斷得了一句話夠不夠專業——
但第二人稱、語助詞、共用詞都是精準的訊號，抓到就一定是。

> 這條規則原本只寫在 `SettingsPage` 的 docstring 裡，然後被違反了兩次
> （「關掉之後要自己從開始選單開它」「睡前 2–3 小時攝取水分才是造成夜間起身的
> 原因，所以…」）。**寫在註解裡的規則擋不住任何人，包括寫下它的人。**
- **破壞性動作在卡片外面**，用分隔線加一段留白隔開，而且是兩段式：點一下先就地問
  「確定要清除所有紀錄嗎？」，再點「刪除」才執行，8 秒沒動作自動收回。
  不用系統對話框——它會在自繪的深色版面中間開一個 Windows 的洞，而且會蓋住正要刪的東西。
- **麵包屑**：副標在設定模式下變成可點的「‹ 喝水紀錄」。右上角那顆返回箭頭太小也沒標籤，
  一條寫著去處的文字連結才是明確的路。

## 深色與淺色

設定頁的「外觀」可選跟隨系統／淺色／深色。調色盤在 `theme.py`。

**淺色是兩層表面，不是一片白**：外框 `#EAEAEA`、卡片 `#FEFEFE`，靠 20 階的亮度差
撐出層次。深色主題還能靠頂緣高光補強，淺色沒有那個工具——白光加在近白上是看不見的。

原本寫死的 42 處顏色收斂成三個角色：`veil(a)` 疊在底色上的薄膜、`ink_a(a)` 帶透明度的
文字、以及語意色。薄膜在淺色主題要**打折**（黑膜在淺底上比白膜在深底上明顯得多）
但也要有**下限**——空槽那一族原本用 14–18 的極淡白，打完折剩 10–13 的黑，
在 `#FEFEFE` 上等於不存在，進度就只剩已完成的部分、讀不出還差多少。

語意色在兩套主題**不是同一個值**：`#4FA8E8` 在 `#FEFEFE` 上對比只有 2.4:1，
當文字讀不到，淺色版壓深成 `#1B7FD4`。

兩處刻意不跟著翻：週曆的打勾（畫在飽和綠點上）、開關的旋鈕（壓在綠色軌道上）。
**它們的底不是頁面底色。** 旋鈕若跟著翻成黑色，開啟狀態會變成綠底黑點，讀起來像壞掉。

分段控制項是相反做法：深色把選中格疊亮，淺色要疊**白**。照抄深色（黑色薄膜）
會得到灰底上一塊更深的灰，讀起來像被停用。

`tests/render_themes.py` 會算文字對比並在低於 3.5:1 時擋下來。顏色多半只能用眼睛看，
但對比有客觀標準。

**島不換主題。** 它是浮在任意桌布上的 HUD，深色是對的，而且狀態顏色
（黃／橘紅／灰／綠）是校準在深色藥丸上的。

## 系統匣選單

自繪（`menu.py`），不用 QMenu。QMenu 在 Windows 上是原生彈出視窗，樣式表改得動
顏色與字，改不動圓角、陰影與外框——它會在一片自繪的介面旁邊開出一塊方角、
用系統字的補丁。跟先前把 QMessageBox 換掉是同一個理由。

用 `Qt.Popup` 讓 Qt 負責「點外面就關」：自己做要處理焦點、多螢幕與「點到自己」的例外，
很容易留下一個關不掉的浮動視窗。彈出位置會自己往螢幕內翻——系統匣在右下角，
照游標往右下展開會被切掉，那是原生選單自動做、自繪就得自己做的事。

### 刻意沒有的東西

**沒有「關閉提醒」總開關、沒有「稍後提醒」、沒有「關掉倒地狀態」、沒有提醒強度調整。**

這個工具的核心是「你無法 dismiss 一個狀態」，而設定面板在結構上就是一顆巨大的關閉鍵。
開放什麼，就等於允許使用者把它關到失效，然後變成「靜音但沒解除安裝」在系統裡躺半年。
**暫停 2 小時已經是出口，那是唯一一個。**

實測支持這個決定：22 次提醒中有 5 次升級到虛弱、2 次到倒地，七次全部以喝水收場
（最快 1 秒、最慢 33 分）。升級機制有效到使用者根本沒感覺它存在——那不是該給人關掉的東西。

### 兩個不用你回答的問題

**起床時間與深夜模式起點由程式自己判斷**（推導的公式與它為什麼拆成兩條，
見上面「排程為什麼分成兩條各自推導」）。使用者只在推導猜錯時才需要動它。

資料不足時（少於 20 筆活動、或找不到 4 小時以上的安靜段）就用預設值，**不亂猜**。
一個猜錯的作息會把整天的次數在使用者還在工作時歸零，那比沒推導更糟。

### 其餘參數

寫死在 `settings.py` 的 `DEFAULTS` 裡（一次喝多少 cc、閒置門檻、升級時間、停留秒數…）。
會改 json 的人可以直接改 `%LOCALAPPDATA%\Sipbar\config.json`，改完重開。

**如果你發現自己一直在忽略它，第一個該調的不是間隔，是先確認桌上有沒有水壺。** 沒水的話提醒等於叫你走去廚房，那是 20 倍行動成本，忽略它是理性的——這個工具解決不了物流問題。

## 喝水紀錄視窗

右鍵島（或系統匣圖示）→「**喝水紀錄**」。內容區 780 寬，高度收到最高那一頁剛好放得下
（含陰影 840×756），可拖曳、右下角可拉大小，Esc 或右上角 × 關閉。紀錄那三頁不捲動，
只有設定頁捲——理由見上面「捲動：設定可以，紀錄不行」。

### 設計核心對齊 Duolingo

Duolingo 的核心不是資料視覺化，是**一個大到你不敢斷掉的數字**，加上**一條看得見的路**。所以排序是：

1. **連續天數** — 火焰＋大數字，佔整張首卡。文案隨狀態改變，連續越長越強調損失（「連續 12 天了，別在今天斷掉」）。
2. **今天的環** — 配角，但一眼看得出還差幾次。
3. **護盾** — 補救額度做成道具展示，就像 Duolingo 的 streak freeze。看得到自己有幾個，才知道斷一天不會歸零。
4. **本週七天** — 範圍小、看得懂、今天很明顯。
5. **你走過的路** — 12 週軌跡，滑鼠移過去看那天的數字。看到自己累積的路，是留下來最強的理由。
6. **成就** — 每一項都有進度條與「還差幾」。**「再 2 天解鎖」比一顆灰掉的徽章有力得多。**

### 刻意拿掉的東西

回應率、平均回應時間、總提醒次數、**倒地次數**、時段分布、達標/有用天數比例。

那些是除錯用的分析數字，對動機沒有幫助。尤其「讓它倒地 28 次」是純粹的失敗計數器，會反效果——沒有人會因為看到自己失敗 28 次而更想繼續。

Phase 1 還需要回應率當判準，所以壓成最底下一行灰字，不讓它污染整個畫面。

### 版面用 Qt 的 layout，不手算座標

初版把每個元素的位置寫成 `paintEvent` 裡的魔術數字，結果同一類 bug 一直重複：卡片高度用猜的所以內容被切掉、對齊靠巧合所以出現三條左緣、字級一改整張版面就跑掉。

現在：**結構交給 layout，文字交給 `QLabel`，只有真正的圖形才自繪**（環、火焰、護盾、週曆、熱力圖、進度條、徽章）。

- 卡片高度由內容決定，不可能再切到內容
- 間距與內距宣告一次（`PAD` / `GAP` / `S1..S5`）
- 換字級自動重排

改版面數字時，動 `stats_window.py` 開頭的常數就好，不要回去改個別座標。

### 質感與動態（Apple）

**字級是系統，不是隨手挑的尺寸。** 六個角色寫在 `stats_window.py` 的 `TYPE`：
`display 64 / title 28 / section 20 / headline 18 / body 17 / caption 15`。

> **15px 是中文的地板。** 實測比較過 14px 的 hinting 變體、加粗、提高對比——都沒用：
> 「續／積／補／標」這類筆畫密的字在 14px 會整團糊住，加粗反而更糟（更多墨跡塞進同樣的格子）。
> **中文小字的瓶頸是像素數，不是字重或對比。**
階層主要靠**字重與顏色**，不靠一直發明新尺寸。大字收緊字距（tracking 負值），小字不收——這是蘋果的做法。
間距只用 4 的倍數（`S1..S5`）。

> **不能照抄蘋果的對比規格。** 蘋果深色模式的次要文字是 60% 不透明度，那是配著
> 拉丁字母訂的——中文在 15px 的筆畫密度高得多，壓到 60% 就糊成一團。
> 這裡次要文字用 78%、第三層用 55%。**小字配低對比不是低調，是壞掉。**
>
> （這段原本的理由寫的是「半透明視窗只能用灰階抗鋸齒」，那個前提是錯的，
> 見上面字體那節。結論不變，但理由換成真的那個。）

**動畫全部由彈簧驅動**（`motion.py`，島與視窗共用同一套物理）：

| 動作 | 行為 |
|---|---|
| 視窗進場 | 淡入 ＋ 往上滑 18px |
| 卡片 | 依序進場，每張間隔 62ms |
| 連續天數 | 數字從 0 跳上來 |
| 火焰 | 從底部長出來 |
| 今日的環 | 掃過去，不是直接出現 |
| 護盾 | 一個一個彈出來 |
| 本週七天 | 一顆一顆彈進來 |
| 軌跡熱力圖 | 斜向擦入，像路一段一段亮起來 |
| 成就進度條 | 由左往右填 |
| 關閉 | 淡出 ＋ 下滑，比進場快 |

**進場彈、退場順**——進場是要抓注意力，退場是要讓開，蘋果一貫的不對稱處理。

**所有位移都是整數，不做縮放。** 縮放會讓 Qt 關掉 hinting，字就糊了。

> 初版是產 HTML 用瀏覽器開，但這台機器的 `.html` 關聯到已經退場的 Internet Explorer，
> `webbrowser.open()` 會靜默失敗——檔案有產出來，就是什麼都沒跳出來。
> 改成原生視窗後，不經瀏覽器、不寫檔案、不靠副檔名關聯，整類問題都消失。

### 兩個刻意的設計

**一、沒開電腦的日子是中性的，不是失敗。** 拍攝日整天不在電腦前，熱力圖上留白，不算斷連續、不累積罪惡感。

**二、每月 2 次補救額度。** 有紀錄但沒達標的日子會自動用掉一次補救，連續不會歸零。

第二點是整個後台最重要的機制。**自我追蹤系統最大的死因不是忘記，是「都破功了乾脆算了」那個崩盤。** 斷一次就歸零的設計會讓你在第一次失手時直接放棄整套東西。

### 成就感從哪來

排序是有意的：**熱力圖 > 連續天數 > 徽章**。

看到自己累積的軌跡（格子一格一格填滿）是最強的；連續天數靠損失趨避；徽章實際的行為影響很小，是附加的。所以熱力圖放在最上面、佔最大版面。

## 判準

**連續 3 天，每天回應率 > 50%。**（喝水紀錄視窗最底下那一行灰字會直接告訴你過了沒。）

- 過了 → 值得投入 Phase 2：自製 PNG 序列動畫、streak 與補救額度
- 沒過 → 問題在行動成本或提醒節奏，回頭調參數。**不要往下加功能，加功能救不了沒人理的工具。**
