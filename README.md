## 開機自啟

在設定頁用「開機時啟動」開關控制。它寫的是登錄檔：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run\WaterPet
```

**用登錄檔而不是 Startup 資料夾的捷徑**，因為工作管理員的「啟動應用程式」分頁
看得到也關得掉——Startup 資料夾裡的捷徑反而是使用者找不到的那一種。
舊版那個 `Startup\喝水動態島.lnk` 已於 2026-08-15 移除（封存在 `..\archive\` 裡）。

開始選單的 `喝水動態島.lnk` 保留著，那是給「Win 鍵打『喝水』」用的，跟自啟無關。
**一個平常隱藏的常駐工具，必須有一個「程式沒在跑也找得到」的入口。**

## 怎麼用

平常它**完全隱藏**，螢幕上不佔任何位置。時間到才從螢幕頂端滑下來。

島上會顯示**連續達標天數**：探頭時「連續 2 天 · 下次約 95 分後」，提醒時「連續 2 天 · 今天 0/7 次」，達標當下標題「今天達標了」、小標「連續 3 天」。

> 連續天數原本只在紀錄視窗裡，但島上每天唯一會變的數字是「今天 N/7 次」——它每天歸零，
> 所以整套連續機制在日常視野中不存在，看起來像每天被重置。
> **一個指標放在使用者看不到的地方，等於不存在。**

- **滑鼠移到螢幕頂端中央** = 島探頭出來（不用等提醒，隨時可以叫它）
- **左鍵點島** = 我剛喝了水（**不管喝幾口都算**）
- **滑鼠移到島上** = 展開看完整訊息
- **右鍵點島** = 選單：喝了 / 暫停 2 小時 / 看回應率 / 結束
- **系統匣圖示** = 同樣的功能，左鍵補水、右鍵選單

### 啟動時它會自己現身

程式一啟動（含開機自啟）會滑下來 4 秒，告訴你它在哪。一個平常完全隱藏的工具，最大的問題是你不知道它在不在、在哪裡——與其叫你去翻系統匣，不如讓它自己出來打招呼。

### 頂端探頭

把滑鼠移到螢幕上緣中段（**中央左右各 320px、上緣往下 10px** 的範圍），島就會滑下來，滑走就收回去。

在 3440px 超寬螢幕上，中央 640px 大約是螢幕正中間那一段。

這條路存在的理由：**島隱藏時如果只剩系統匣可以操作，等於把唯一入口交給一個 Windows 預設會摺疊起來的地方。** 匣圖示還在，但你不需要依賴它。

### 系統匣圖示要找什麼？

**它顯示為 `pythonw`。** 程式是用 Python 執行的，Windows 只認執行檔名稱，所以搜尋「喝水」永遠找不到。

固定到工作列的路徑：

```
設定 → 個人化 → 工作列 → 其他系統匣圖示 → 找到 pythonw → 開啟
```

或是點工作列的「^」，把那顆**藍色圓臉圖示**拖到工作列上。

匣圖示的顏色就是目前狀態，滑過去會顯示「喝水動態島 · 今天 N/6 次」。

### 為什麼單位是「次」不是「杯」

你的杯子 500cc，但被提醒時你只會喝個幾口，不會把 500cc 灌完。如果計數單位是「杯」，你只有兩條路：虛報，或是因為「才喝兩口不好意思按」而不按——**前者讓數字造假，後者讓島一直掛在那邊、你開始無視它。兩條都是死路。**

所以單位是「補水次數」：**點下去只宣稱「我喝了水」，不宣稱喝了多少。** 沒有誇大的成分，就沒有虛報的心理壓力。

cc 只在選單和統計裡顯示，而且標明是估算（預設一次抓 250cc）。那是參考值，不是紀錄。

## 五個狀態

| 狀態 | 顏色 | 島的行為 | 什麼時候 |
|---|---|---|---|
| 正常 | 藍 | **完全隱藏** | 剛喝完 |
| 口渴 | 黃 | 滑下來展開 6 秒，縮成小藥丸但不消失 | 到間隔時間 |
| 虛弱 | 橘紅 | 展開 8 秒，縮成中等藥丸但不消失 | 忽略 15 分鐘 |
| 倒地 | 灰 | **全展開，不收合也不消失** | 忽略 40 分鐘 |
| 達標 | 綠 | 閃 1.8 秒確認訊息，然後滑走 | 當天補水滿 6 次 |

**沒有關閉按鈕，這是故意的。** 你趕不走它，只能靠喝水讓它走——消失是獎勵，不是逃生出口。

「喝完就隱藏」除了不擋畫面，還有一個更重要的作用：**出現本身是比狀態改變更大的知覺事件。** 永遠在畫面上的東西一定會被習慣化，會消失的東西每次回來都是新的。

## 節奏（依你的實際狀況設的）

- **計時基準是「在電腦前的連續時間」**，不是牆上時鐘。鍵鼠閒置 15 分鐘就暫停計時，回來續計。
  提醒發在你不能行動的時候，只會訓練出無視的反射——那個反射會連 Discord 提醒頻道的工作提醒一起污染。
- **多久跳一次：白天約 60–80 分鐘一次**（70 分鐘 ±10 隨機抖動，抖動是為了對抗「整點提醒」的可預測性）。深夜 23:00 後拉長到 90–110 分鐘。
  但那是「在電腦前的時間」，不是牆上時間——離開電腦超過 15 分鐘就暫停計時，所以實際可能兩小時才跳一次。
  **不用記這個數字**：把滑鼠移到螢幕上緣中間，它會直接告訴你「下次約 25 分後」。
- 每日目標 7 次（估算約 1400cc，只算來自提醒的部分）。達標後當天不再出現。

### 這些數字怎麼來的（依國健署資料 + 體重 65kg 推算）

- **每日白開水目標約 1950cc**：`體重 65 × 30cc`，與國健署「成人每日 6–8 杯（240ml/杯）＝ 1440–1920cc」相符。
- **每次約 200cc、小口慢喝**：國健署明講 1 小時內不喝超過 1000cc，一次灌下去身體來不及吸收。
- **1950 ÷ 200 ≈ 一天 10 次**，但工具只在你坐電腦前時計時。起床那杯（國健署建議 300–500cc）與三餐湯水在它管不到的地方，所以工具承擔 **7 次**。
- **7 次 × 70 分鐘 = 490 分鐘 ≈ 8.2 小時**，剛好鋪滿一個工作日的電腦時間。原本的 6 次 × 60 分鐘只有 6 小時，會在下午就達標、然後整晚安靜。

夏天在外拍攝、流汗多的日子要另外補，工具管不到那段。這是一般性的公共衛生資訊，不是針對個人健康狀況的醫療建議。
- **23:00 之後間隔拉長到 90 分鐘**，文案有一半機率換成「小口就好」。你 12 點到 3 點才睡，但半夜灌水會壞掉睡眠。
- **一天的分界在早上 5:00，不是午夜。** 不然你凌晨兩三點的工作會被切成兩天，次數莫名歸零。
- 拍攝日電腦沒開就完全不計時，不累積罪惡感。
- **計時會跨重啟保存。** 開機自啟、程式當掉、手動重開都不會把累積的時間丟掉，間隔也不會重擲。
  每分鐘落檔一次，加上啟動時與每次補水／暫停都會存，所以最多只會丟一分鐘。
  距上次存檔超過 12 小時（睡了一覺、電腦關一整天）才會重新開始一段。

## 動畫

用彈簧物理，不是 easing curve——這是蘋果 UI 動畫跟一般網頁動畫最根本的差別。easing 是預先畫好的曲線，被打斷只能從頭再走；彈簧有速度與慣性，被打斷時帶著當下的速度轉向新目標。

| 用途 | response | damping | 過衝 | 收斂 |
|---|---|---|---|---|
| 展開 | 0.40 | 0.70 | +2.0% | 567ms |
| 收合 | 0.52 | 1.00 | 0% | 1100ms |
| 現身 | 0.46 | 0.72 | +1.7% | 667ms |
| 隱藏 | 0.36 | 1.00 | 0% | 833ms |
| 內容 | 0.34 | 1.00 | 0% | 800ms |

覺得手感不對就調這幾個數字（在 `island.py` 的 `_target_expand` / `_target_reveal` / `_target_content`）。**response 是週期，越小越快；damping 越小彈越多，1.0 完全不過衝。**

## 字體

`FONT_FAMILY` / `FONT_TITLE_PX`（20）/ `FONT_SUB_PX`（15）在 `island.py` 開頭。

字級調大之後藥丸也要跟著加寬（展開尺寸 384→430），否則小標會被省略號截掉。
測試 17b 會用字體度量檢查最長的三段文字放不放得下——**改字級或改目標次數時，先跑它**。

> **一個被推翻的說法**：先前這裡寫著「半透明視窗用不了 ClearType，只能灰階抗鋸齒」。
> 實測後不成立——不透明 QPixmap、半透明 QImage、一般視窗、半透明視窗，四者的彩色像素比例
> 都是 79.8%，次像素渲染一直都在作用。**問題不在視窗形式，在字型。**

**字體現在隨程式散布**（`assets/fonts/`，見 `typeface.py`）。以前是假設機器上裝了
Noto Sans TC——那對自用成立，發布出去就不成立，而且要不到時 Qt 是**靜默替換**的。

> **字體序列裡每多一個中文字體，就多幾百 MB。** 一度把 fallback chain
> 掛在 QFont 上當保險，結果島畫出文字後記憶體從 89MB 漲到 612MB、handle 從 342 到 1153——
> Qt 為了決定每個字元由誰來畫，會把序列上每個字體的字符表整份載進來，中文字體動輒三萬個字符。
> 現在隨附字體載成功就只用它一個，chain 只在真的載不起來時才用。
> `tests/test_font_memory.py` 把這條線釘住了。

真正有效的三件事：

1. **字型用 Noto Sans TC，內文用 Medium 500。**
   實測比較過 default / freetype / gdi 三種引擎與三種字型：引擎差異不大，
   但 Microsoft JhengHei UI 的 Regular 筆畫太細，淺色字在深色底上因 gamma 更顯薄。
   關鍵是 **Noto Sans TC 有真正的 Medium 500（精確匹配），JhengHei UI 只有
   Regular / Light / Bold**——沒有中間字重可以補償。
2. **靜止時不套任何變形。** 非整數的位移或縮放會讓 Qt 關掉 hinting，字就糊。
   動畫進行中才套，一停下來就歸零。
3. **尺寸用像素不用點數**（點數會經 DPI 換算成小數），需要精確對齊時用字體度量算整數基線。

60fps 迴圈只在彈簧還在動的時候跑，靜止就停——常駐工具不能無條件重繪。
實測 CPU 0.4%、RAM 約 84MB（比先前的 59MB 多的部分是隨程式散布的字體）。

## 設定

右鍵島或系統匣 →「設定」，或在紀錄視窗右上角點齒輪。改完即時生效，不用重開。

**面板上只有四項，這是刻意的。** 篩選標準只有一條：不改就會讓工具對這個人失效。

| 設定 | 為什麼它活下來 |
|---|---|
| 體重（可留空） | 50kg 和 90kg 的目標差一倍，這是唯一擋不掉的個體差異 |
| 提醒間隔 | 每個人在電腦前的時間結構不同 |
| 習慣起床時間 | 一天從幾點開始算。程式會給初始建議，但推導對雜訊敏感，必須能改 |
| 外觀 | 跟隨系統／淺色／深色 |
| 島顯示在哪個螢幕 | 多螢幕猜不到（只有一個螢幕時不顯示這一項） |
| 開機時自動啟動 | 沒人會自己去 Startup 資料夾 |

加上一塊唯讀的排程說明、資料位置，以及跟卡片隔開的「清除紀錄」。

### 為什麼問「起床時間」而不是「換日時間」

「換日」是系統概念，使用者得反推該填什麼；起床時間是他本來就知道的事實。

而且**語意上更對**。程式推導出來的安靜段起點其實是「你停止用電腦的時間」，
拿它當換日有個破口：哪天你做過頭做到那個時刻之後，換日會在你還在工作時
把當天次數歸零、前一天的紀錄當場被切斷。起床時間沒有這個問題——
你還在電腦前就代表還沒睡，那就還是同一天。

### 排程為什麼分成兩條各自推導

深夜模式原本是「換日 − 6 小時」。換日改成起床時間之後那條公式就沒依據了
（起床 11:00 會推出深夜模式 05:00，完全反了），所以拆開：

- **起床時間** = 最長安靜段的**結束**（你回到電腦前的時刻）
- **深夜模式起點** = 每天最後一次活動的**中位數** − 3 小時

「每天」由起床時間定義，所以第二條建立在使用者已經給定的值上。
往前 3 小時是有依據的：睡前 2–3 小時的攝取才是造成夜間起身的區間。

取中位數不取平均：一次特例（熬夜、或程式重啟造成的雜訊事件）會把平均拉走，
卻撼動不了中位數。**連續段偵測則相反——實測三筆多餘的事件就讓它從 6 小時
縮到 3 小時、直接回 None。** 這正是起床時間必須可手動調整的理由。

還有一道防線：使用者可以把起床時間設在自己實際還在活動的時段裡，
那時「一天」的邊界會切在活動中間，中位數變成 23 小時、推出 07:00 這種垃圾。
清醒時段落在 8–20 小時之外就代表前提不成立，退回「起床 − 11 小時」。

### 捲動：設定可以，紀錄不行

紀錄那三頁不捲動，理由在下面「刻意拿掉的東西」那節：成就與軌跡是要讓人逛的，
藏在捲軸下面等於不存在。

**但設定不是拿來逛的，是拿來查的**——帶著「我要改間隔」的目的進來，找到、改完、離開。
這種頁面捲動是標準做法。所以規則從「一律不捲」改成依頁面性質決定。

視窗高度不變（771，跟紀錄頁一致），捲的是內容區——換頁時視窗不會跳動。
捲軸自繪：細、圓角、軌道全透明；內容區上下緣各一道 18px 的漸層，暗示「還有」。
那道漸層是還債：不捲動的面板一眼就知道有多少東西，捲動的沒有。

（第一版把漸層做成 28px，結果它蓋到完整顯示、讀得到的那幾行，
把說明段落洗成半透明。遮罩的作用是暗示還有，不是把內容變淡。）

### 版面用網格，不是逐項微調

設定列看起來「沒排好」，多半不是對齊錯了，是**每一列高度都不一樣**——有說明的列
自己長高、沒說明的列自己縮短，右側控制項的中心線每列落在不同地方，眼睛掃下來就是歪的。

所以列高釘死成四種，全部是 8 的倍數（`stats_window.py` 開頭的網格常數）：

| 常數 | 高度 | 用在哪 |
|---|---|---|
| `ROW_TALL` | 56 | 有說明的設定列（標題 + 說明兩行） |
| `ROW_FLAT` | 48 | 單行的設定列。裡面有控制項，要留得下點擊區 |
| `ROW_INFO` | 40 | 唯讀資訊列。沒有東西要點就不需要那個餘裕 |
| `ROW_SECTION` | 32 | 區塊標題 |

> 這四個值一度是 48/40/32/24——那是為了把設定頁擠進 558px 壓出來的，不是設計判斷。
> 改成可捲動之後就沒有理由再擠，各放寬一級。**版面被空間逼出來的妥協，
> 要在空間解禁時退回去**，不然那些妥協會被後人當成刻意的設計而繼續沿用。

**互動列比資訊列高，是因為滑鼠需要空間，不是為了好看。** `test_settings.py` 第 12d 節
會擋下任何不在這四種之列的列高。

### 幾條寫死的規矩

- **單位貼在控制項旁邊**（`65` **公斤**、`75` **分鐘**），不寫進說明裡。單位是那個值的
  一部分，塞進說明就變成要讀完一句話才知道自己在設什麼。
- **不用內部術語。** 「換日」「深夜模式」使用者讀不出是什麼，還會誤解成「幾點睡」。
  改成講結果並把數字寫出來：「今日次數歸零　每天 05:00」「夜間放慢提醒　23:00 起改為每 65 分」。
- **破壞性動作在卡片外面**，用分隔線加一段留白隔開，而且是兩段式：點一下先就地問
  「確定要清除所有紀錄嗎？」，再點「刪除」才執行，8 秒沒動作自動收回。
  不用系統對話框——它會在自繪的深色版面中間開一個 Windows 的洞，而且會蓋住正要刪的東西。
- **麵包屑**：副標在設定模式下變成可點的「‹ 喝水紀錄」。右上角那顆返回箭頭太小也沒標籤，
  一條寫著去處的文字連結才是明確的路。

## 深色與淺色

設定頁的「外觀」可選跟隨系統／淺色／深色。調色盤在 `theme.py`。

**淺色是兩層表面，不是一片白**：外框 `#EAEAEA`、卡片 `#FEFEFE`，靠 20 階的亮度差
撐出層次。深色主題還能靠頂緣高光補強，淺色沒有那個工具——白光加在近白上是看不見的。

原本寫死的 42 處顏色收斂成三個角色：`veil(a)` 疊在底色上的薄膜、`ink_a(a)` 帶透明度的
文字、以及語意色。薄膜在淺色主題要**打折**（黑膜在淺底上比白膜在深底上明顯得多）
但也要有**下限**——空槽那一族原本用 14–18 的極淡白，打完折剩 10–13 的黑，
在 `#FEFEFE` 上等於不存在，進度就只剩已完成的部分、讀不出還差多少。

語意色在兩套主題**不是同一個值**：`#4FA8E8` 在 `#FEFEFE` 上對比只有 2.4:1，
當文字讀不到，淺色版壓深成 `#1B7FD4`。

兩處刻意不跟著翻：週曆的打勾（畫在飽和綠點上）、開關的旋鈕（壓在綠色軌道上）。
**它們的底不是頁面底色。** 旋鈕若跟著翻成黑色，開啟狀態會變成綠底黑點，讀起來像壞掉。

分段控制項是相反做法：深色把選中格疊亮，淺色要疊**白**。照抄深色（黑色薄膜）
會得到灰底上一塊更深的灰，讀起來像被停用。

`tests/render_themes.py` 會算文字對比並在低於 3.5:1 時擋下來。顏色多半只能用眼睛看，
但對比有客觀標準。

**島不換主題。** 它是浮在任意桌布上的 HUD，深色是對的，而且狀態顏色
（黃／橘紅／灰／綠）是校準在深色藥丸上的。

## 系統匣選單

自繪（`menu.py`），不用 QMenu。QMenu 在 Windows 上是原生彈出視窗，樣式表改得動
顏色與字，改不動圓角、陰影與外框——它會在一片自繪的介面旁邊開出一塊方角、
用系統字的補丁。跟先前把 QMessageBox 換掉是同一個理由。

用 `Qt.Popup` 讓 Qt 負責「點外面就關」：自己做要處理焦點、多螢幕與「點到自己」的例外，
很容易留下一個關不掉的浮動視窗。彈出位置會自己往螢幕內翻——系統匣在右下角，
照游標往右下展開會被切掉，那是原生選單自動做、自繪就得自己做的事。

### 刻意沒有的東西

**沒有「關閉提醒」總開關、沒有「稍後提醒」、沒有「關掉倒地狀態」、沒有提醒強度調整。**

這個工具的核心是「你無法 dismiss 一個狀態」，而設定面板在結構上就是一顆巨大的關閉鍵。
開放什麼，就等於允許使用者把它關到失效，然後變成「靜音但沒解除安裝」在系統裡躺半年。
**暫停 2 小時已經是出口，那是唯一一個。**

實測支持這個決定：22 次提醒中有 5 次升級到虛弱、2 次到倒地，七次全部以喝水收場
（最快 1 秒、最慢 33 分）。升級機制有效到使用者根本沒感覺它存在——那不是該給人關掉的東西。

### 兩個不用你回答的問題

**換日時間與深夜模式起點由程式自己判斷。** 它把活動紀錄攤成 24 格直方圖，找出最長的
一段沒在用電腦的時間，把換日設在那一段的起點——那是一天當中最安全的換日點，因為那時候
你不在。深夜模式從換日往前推 6 小時。

以本機真實資料驗證：54 筆活動中 05:00–10:00 完全是零 → 換日 05:00、深夜 23:00，
跟原本手動調出來的值一致。資料不足時（少於 20 筆活動、或找不到 4 小時以上的安靜段）
就用預設值，不亂猜。

### 其餘參數

寫死在 `settings.py` 的 `DEFAULTS` 裡（一次喝多少 cc、閒置門檻、升級時間、停留秒數…）。
會改 json 的人可以直接改 `%LOCALAPPDATA%\WaterPet\config.json`，改完重開。

**如果你發現自己一直在忽略它，第一個該調的不是間隔，是先確認桌上有沒有水壺。** 沒水的話提醒等於叫你走去廚房，那是 20 倍行動成本，忽略它是理性的——這個工具解決不了物流問題。

## 資料放哪

`%LOCALAPPDATA%\WaterPet\`

- `config.json` — 設定。**從程式旁邊搬過來的**：打包成 exe 裝進 Program Files 之後
  那個目錄不可寫，寫入會靜默失敗（改了設定、沒有錯誤、重開全部復原）。
  舊檔會自動搬過來一次，原檔留著當備份。
- `state.json` — 當天次數、累積的在電腦前時間、本輪間隔、暫停狀態、最後存檔時間
- `events.jsonl` — 事件紀錄，回應率就是從這裡算的

要重來用設定頁底部的「清除所有紀錄」（設定會留著），或把整個資料夾刪掉。

## 喝水紀錄視窗

右鍵島（或系統匣圖示）→「**看喝水紀錄**」。760×880，可捲動、可拖曳、右下角可拉大小，Esc 或右上角 × 關閉。

### 設計核心對齊 Duolingo

Duolingo 的核心不是資料視覺化，是**一個大到你不敢斷掉的數字**，加上**一條看得見的路**。所以排序是：

1. **連續天數** — 火焰＋大數字，佔整張首卡。文案隨狀態改變，連續越長越強調損失（「連續 12 天了，別在今天斷掉」）。
2. **今天的環** — 配角，但一眼看得出還差幾次。
3. **護盾** — 補救額度做成道具展示，就像 Duolingo 的 streak freeze。看得到自己有幾個，才知道斷一天不會歸零。
4. **本週七天** — 範圍小、看得懂、今天很明顯。
5. **你走過的路** — 12 週軌跡，滑鼠移過去看那天的數字。看到自己累積的路，是留下來最強的理由。
6. **成就** — 每一項都有進度條與「還差幾」。**「再 2 天解鎖」比一顆灰掉的徽章有力得多。**

### 刻意拿掉的東西

回應率、平均回應時間、總提醒次數、**倒地次數**、時段分布、達標/有用天數比例。

那些是除錯用的分析數字，對動機沒有幫助。尤其「讓它倒地 28 次」是純粹的失敗計數器，會反效果——沒有人會因為看到自己失敗 28 次而更想繼續。

Phase 1 還需要回應率當判準，所以壓成最底下一行灰字，不讓它污染整個畫面。

### 版面用 Qt 的 layout，不手算座標

初版把每個元素的位置寫成 `paintEvent` 裡的魔術數字，結果同一類 bug 一直重複：卡片高度用猜的所以內容被切掉、對齊靠巧合所以出現三條左緣、字級一改整張版面就跑掉。

現在：**結構交給 layout，文字交給 `QLabel`，只有真正的圖形才自繪**（環、火焰、護盾、週曆、熱力圖、進度條、徽章）。

- 卡片高度由內容決定，不可能再切到內容
- 間距與內距宣告一次（`PAD` / `GAP` / `S1..S5`）
- 換字級自動重排

改版面數字時，動 `stats_window.py` 開頭的常數就好，不要回去改個別座標。

### 質感與動態（Apple）

**字級是系統，不是隨手挑的尺寸。** 六個角色寫在 `stats_window.py` 的 `TYPE`：
`display 64 / title 28 / section 20 / headline 18 / body 17 / caption 15`。

> **15px 是中文的地板。** 實測比較過 14px 的 hinting 變體、加粗、提高對比——都沒用：
> 「續／積／補／標」這類筆畫密的字在 14px 會整團糊住，加粗反而更糟（更多墨跡塞進同樣的格子）。
> **中文小字的瓶頸是像素數，不是字重或對比。**
階層主要靠**字重與顏色**，不靠一直發明新尺寸。大字收緊字距（tracking 負值），小字不收——這是蘋果的做法。
間距只用 4 的倍數（`S1..S5`）。

> **半透明視窗不能照抄蘋果的對比規格。** 蘋果深色模式的次要文字是 60% 不透明度，但那是給有
> ClearType 次像素渲染的環境。半透明視窗只能用灰階抗鋸齒、字本來就偏細，再壓到 60% 就變成
> 讀不到。這裡次要文字用 78%、第三層用 55%。**小字配低對比不是低調，是壞掉。**

**動畫全部由彈簧驅動**（`motion.py`，島與視窗共用同一套物理）：

| 動作 | 行為 |
|---|---|
| 視窗進場 | 淡入 ＋ 往上滑 18px |
| 卡片 | 依序進場，每張間隔 62ms |
| 連續天數 | 數字從 0 跳上來 |
| 火焰 | 從底部長出來 |
| 今日的環 | 掃過去，不是直接出現 |
| 護盾 | 一個一個彈出來 |
| 本週七天 | 一顆一顆彈進來 |
| 軌跡熱力圖 | 斜向擦入，像路一段一段亮起來 |
| 成就進度條 | 由左往右填 |
| 關閉 | 淡出 ＋ 下滑，比進場快 |

**進場彈、退場順**——進場是要抓注意力，退場是要讓開，蘋果一貫的不對稱處理。

**所有位移都是整數，不做縮放。** 縮放會讓 Qt 關掉 hinting，字就糊了。

> 初版是產 HTML 用瀏覽器開，但這台機器的 `.html` 關聯到已經退場的 Internet Explorer，
> `webbrowser.open()` 會靜默失敗——檔案有產出來，就是什麼都沒跳出來。
> 改成原生視窗後，不經瀏覽器、不寫檔案、不靠副檔名關聯，整類問題都消失。

### 兩個刻意的設計

**一、沒開電腦的日子是中性的，不是失敗。** 拍攝日整天不在電腦前，熱力圖上留白，不算斷連續、不累積罪惡感。

**二、每月 2 次補救額度。** 有紀錄但沒達標的日子會自動用掉一次補救，連續不會歸零。

第二點是整個後台最重要的機制。**自我追蹤系統最大的死因不是忘記，是「都破功了乾脆算了」那個崩盤。** 斷一次就歸零的設計會讓你在第一次失手時直接放棄整套東西。

### 成就感從哪來

排序是有意的：**熱力圖 > 連續天數 > 徽章**。

看到自己累積的軌跡（格子一格一格填滿）是最強的；連續天數靠損失趨避；徽章實際的行為影響很小，是附加的。所以熱力圖放在最上面、佔最大版面。

## 判準

**連續 3 天，每天回應率 > 50%。**（右鍵匣圖示 → 看回應率，程式會直接告訴你過了沒。）

- 過了 → 值得投入 Phase 2：自製 PNG 序列動畫、streak 與補救額度
- 沒過 → 問題在行動成本或提醒節奏，回頭調參數。**不要往下加功能，加功能救不了沒人理的工具。**

## 已知限制（不修）

全螢幕遊戲、全螢幕影片預覽時，always-on-top 視窗會被 Windows 蓋掉。那些情境本來就不該打斷，不做 hack 去繞。

收合時島佔螢幕頂端中央 144px 寬，會擋掉最大化視窗標題列那一段的拖曳。但它只在你該喝水時才出現，平常完全不在。
